## Rust release binaries

The CLI/router and Windows/Linux desktop tray are built from the dependency
versions pinned in `Cargo.lock`. The macOS application remains native Swift.
Every desktop archive and GitHub release includes `THIRD_PARTY_LICENSES.txt`,
generated by `scripts/third_party_licenses.py` from the complete license and
notice files packaged with those exact Cargo dependencies. When a crate omits
its license file, `scripts/licenses/` contains an exact upstream copy pinned to
the crate's source commit and version. That file includes
target-specific dependencies, their source locations, SPDX declarations,
copyright notices, and full license texts. Release builds fail if a dependency's
packaged license text cannot be found.

Major components include Tokio, Axum, Hyper, Reqwest, Rustls, Tungstenite, Serde,
Chrono, toml_edit, notify, fs2, tray-icon, muda, ksni, zbus, and windows-sys.
Linux uses the native D-Bus StatusNotifierItem backend of tray-icon and does not
link GTK or libappindicator. Windows uses native system APIs. The generated file
is the complete license inventory; this overview is not a replacement for it.

## Retained Go reference implementation

The original Go sources remain in the repository for behavioral comparison and
tests during the Rust migration. The following notices cover those retained
sources and historical Go releases; Go components are not linked into the Rust
release binaries.

## Separately installed components

Native Codex and Claude Code clients are installed and licensed separately by
their respective publishers. Noria invokes these installed executables directly
for account quota readings, without distributing either client or an SDK.

Documentation font licenses are distributed beside the corresponding font
assets under `docs/public/fonts`.

## Design reference

The project reviewed CLIProxyAPI (https://github.com/router-for-me/CLIProxyAPI)
as a reference for native provider protocol integration. Noria does not vendor
CLIProxyAPI or its multi-provider execution framework.
